# IPM接入时的静态测试迁移记录

## 反复失败的原因

既有冒烟测试对源码做字符串匹配，假设工具只有两种模式、完整镜像只用于网关、版本全部只读、子任务标题固定。新增模式、标题绑定和 MCU 旧版本输入后，连续触发多个旧断言；其中先查源码片段再用返回位置切片的测试，在片段不再存在时还触发了索引越界。

## 本次处理

- 先核对新需求，再更新确实已失效的文案和能力断言，保留原有行为检查。
- 新增真实界面模型回归，使用独立临时工作区和内存凭据验证三模式切换、包过滤及 MCU 版本语义。
- 对 MCU 向量、容量、协议编码、受理重试、SID 隔离和取消竞争使用行为测试，不以源码字符串存在代替正确性。
- WPF 自包含应用被测试项目引用时，测试项目需匹配 Windows 目标、运行时和自包含配置；否则出现 `NETSDK1151`。
- 批量修改 XAML 属性时避免对同一标签重复插入 `Visibility`；每次修改后用 WPF 编译器验证 XML。
- 同一文件的多段补丁按源码顺序排列，并先核对上下文；逆序片段可能使补丁定位失败。
- 下载联调新增任务名称分支后，完整源码字符串断言再次触发。保留统一名称格式，将方向变量扩展为联调标签，并补充真实入队、执行校验和预计运行版本测试，避免为通过静态检查而改回错误行为。

## 后续原则

布局约束可继续使用有限的静态检查；涉及模式、包类型、版本和任务状态的断言应优先执行实际模型或模拟协议流程。查找字符串的位置必须先验证非负再使用，避免用二次索引错误掩盖原始断言失效。
