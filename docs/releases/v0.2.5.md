# v0.2.5

这是 OTA 测试平台的 Patch 工作流与升级状态展示优化版本，重点解决时间戳文件名难以辨认和累积过多的问题，并精简低频操作入口。

## Patch 命名与导入

- Patch 自动命名不再附加 Unix 时间戳，改为使用用户填写的后缀，例如 `socket-v1-to-v2-jp01.patch`。
- 用户后缀为必填项，最多 16 个 ASCII 字母或数字，并分别保存 EcoLink 与传统模式的配置。
- 同一用户保持后缀不变时，再次制作相同版本方向的 Patch 会复用文件名并覆盖本地产物，避免目录持续累积重复文件。
- 不同用户可自行约定不同后缀，减少共同发布目录中的文件名冲突。
- 移除“导入 Patch 验证”、还原方向和手动验证按钮；工具自产 Patch 仍会在生成阶段自动执行双向原生还原验证。
- 导入外部 Patch 时必须同时提供同名 `.json` 清单；缺少清单或清单校验失败时直接拒绝导入。
- 输出目录中已有的无有效清单 Patch 仍会显示在详情列表中，但不能用于升级或发布。

## 升级状态展示

- 升级状态机右上角实时显示当前版本方向，例如 `计划 1/1 · 单次 · v0.1 → v0.2`。
- 循环升级在正向、反向及间隔阶段同步切换版本方向，便于直接确认当前正在执行的升级链路。
- 任务队列执行和版本复查阶段继续保留版本方向提示。

## 升级说明

- v0.2.3 可通过工具内更新直接升级到 v0.2.5。
- Patch 内容格式、Manifest 字段、升级任务、历史记录和报告数据库保持兼容。
- 从本版本开始，导入外部差分 Patch 必须携带由工具生成的同名 `.json` 清单。
