## 更新内容

### 升级任务与版本校验

- 将单次升级拆分为“正向升级”和“反向升级”，根据当前设备版本与 Patch 元数据只启用符合条件的方向，正向完成后可直接执行反向升级。
- 自动关联最新且类型、方向、版本匹配的正反向 Patch，修复正向列表默认选中反向 Patch 的问题。
- 增加 Gateway 当前版本手动查询；升级前使用基础信息中的 OTA 软件版本校验所选方向。
- 增加异步拓展器版本手动查询协议，异步升级不再错误使用同步板版本进行方向和底版本校验。
- 修正同步板与异步板共板场景的 Patch 类型判断，并按升级类型展示有效阶段，异步升级不再显示 Node 下游升级阶段。

### 多设备任务可靠性

- 多个 Extender 同时升级时，单个子任务失败后继续等待其余子任务结束，再汇总最终结果，避免提前终止仍在正常运行的设备。
- Gateway 或子任务确认失败后停止状态轮询，并主动发送取消请求，避免失败任务继续占用轮询与执行状态。
- Node 列表响应兼容未知版本字段；版本与 RSSI 同时为 0 的历史或无效占位记录不会进入可升级列表。
- 修复刷新 Node 后已选类型未自动勾选匹配节点，以及节点无法手动勾选的问题。

### MQTT 与主题管理

- Gateway dev ID 支持最近使用记录，可直接选择历史 ID 后订阅。
- 订阅新的 Gateway 主题前自动取消旧主题，确保同一时间只保留一组上行订阅和下行发布主题。
- 切换 Gateway 主题时自动清空 MQTT 收发记录，避免不同设备消息混淆。
- 补充 MQTT 3.1.1 `UNSUBSCRIBE` 支持，并同步维护重连订阅集合。

### Patch 与发布操作

- Patch 列表增加发布标记；公网发布只上传本次勾选的 Patch，取消勾选不会删除源文件。
- 修复 Patch 列表出现滚动条时的横向抖动和末项显示不完整问题。
- 本地 HTTP Range 服务停止后自动回退到公网 Patch 地址；仅在本地服务实际运行时优先使用本地地址。
- 循环次数并入“循环升级设置”，统一固定间隔、随机间隔和循环次数布局。

### 界面一致性

- 应用信息、警告、错误和确认弹框统一为工具内样式，并继续支持按 `Enter` 确认。
- Gateway、Extender 和 Node 使用一致的手动刷新入口，查询结果变化后及时刷新升级按钮可用状态。

## 升级说明

- 已安装 v0.1.2 或 v0.1.3 的用户可以直接使用工具内“检查更新”下载并安装 v0.1.4。
- 建议 Async 固件同步修复 Node 查询返回历史注册列表的问题；工具端会过滤版本和 RSSI 同时为 0 的无效记录，但原始 MQTT 消息仍会完整保留用于排查。
