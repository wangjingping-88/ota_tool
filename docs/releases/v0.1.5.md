## 更新内容

### 异步设备查询协议

- Node 列表查询由旧 `cmd=10/11` 切换为 `cmd=100 + 0x0E/0x0F`，Sync/Async 状态查询由旧 `cmd=12/13` 切换为 `cmd=100 + 0x10/0x11`，不再回退旧协议。
- 上行响应支持单个 JSON 对象和数组包装，兼容 Hex、Base64 数据；严格校验应用层 Header、命令、长度、设备数量、Node ID、RSSI 和 SNR。
- 数组内出现多个 Extender 的同命令响应时按完整 Extender ID 精确匹配；其他 Extender 的畸形项、发送 ACK、迟到响应和重复响应不会覆盖目标查询结果。
- 同一 Extender 的 Node 与状态查询严格串行，不同 Extender 保持并行；查询超时自动重试，单板失败不丢弃其他成功结果。

### Extender 与 Node 展示

- Extender 区域改为完整遥测卡片，统一展示 Sync/Async 版本、Async 地址、Sync RSSI/SNR、Node 在线数和总数，避免窄区域截断关键信息。
- 协议原始版本字节统一格式化，例如 `1` 显示为 `v0.1`、`23` 显示为 `v2.3`；Patch 校验和 MQTT 下发仍使用原始字节，保持协议兼容。
- Node 列表仅展示在线设备，支持 `-200～0 dBm` RSSI；版本为 `0` 或 `255` 的在线设备显示“未知版本”并禁止升级。
- 刷新结果显示协议总数、在线显示数和失败 Extender 数，并将新增状态字段持久化；旧设置文件可以继续直接加载。

### OTA 缓存复用状态

- 支持 Gateway 上报 `package_source`、缓存命中统计、查询耗时和子任务缓存结果。
- Gateway 命中 Sync 已缓存 OTA 包时，将传输阶段显示为“复用缓存”，明确标记已跳过 Gateway 到 Sync 数据传输，并继续展示后续 Node 下游升级阶段。
- 兼容尚未增加 `SKIPPED` 状态、仅通过 `CACHE_REUSED` 原因表示缓存复用的 Gateway 状态响应；旧 Gateway 未上报缓存字段时保持原有阶段展示。
- 新增《Gateway 到 Sync 缓存复用状态对接说明》，明确字段、状态机与工具展示约定。

### 稳定性

- HTTP 文件完整正文校验增加临时异常和正文截断重试，降低 Patch 下载链路偶发中断导致的启动失败。
- 修复缓存复用原因显示为原始英文代码的问题，并增强旧报告缺失可选字段时的空值兼容。
- 发布脚本在清理输出目录前检查是否仍有程序从该目录运行，目录被占用时完整中止，避免旧预览包被部分删除后缺少 Patch 验证脚本或内置工具。

## 兼容与升级说明

- 本版本的异步查询不兼容旧 `cmd=10～13` 固件。实机联调和发布时，Gateway、Sync、Async 与工具必须成套升级；Async 固件需提供文档规定的 5 字节 Node 项和固定 6 字节状态响应。
- 已安装 v0.1.2、v0.1.3 或 v0.1.4 的用户可以直接使用工具内“检查更新”下载并安装 v0.1.5。
- v0.1.0 或 v0.1.1 仍需先手动升级到 v0.1.2 或更高版本，之后即可使用工具内在线升级。
