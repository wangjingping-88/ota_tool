## 更新内容

### 升级任务可靠性

- 修复 `cmd=8` 状态响应延迟时被误判为查询失败的问题：默认等待时间调整为 8 秒，连续超时仅提示状态暂不可用，并继续退避轮询。
- 支持接收当前任务最近查询序号对应的延迟状态响应，收到有效响应后恢复正常轮询，不再中断仍在下游运行的升级任务。
- Patch HTTP 校验对网络异常及 `408`、`425`、`429`、`500`、`502`、`503`、`504` 临时响应自动重试，提高启动单次和循环升级时的稳定性。

### 循环升级与状态展示

- 循环升级启动前增加统一确认弹框，集中展示轮数、正反向顺序、单次间隔、Patch 文件和下载地址。
- 循环升级结束后与单次升级一致显示结果弹框，并通过绿色“通过”或红色“失败”印章直观标识结果。
- 升级状态机和历史报告根据网关、同步拓展器、异步拓展器、Node 升级类型仅显示有效阶段，避免无关阶段干扰判断。
- 修复直接启动循环升级时前置状态与单次升级不一致的问题。

### 日志分析

- 日志解析器支持自动识别同一批日志中的全部 SID，按循环轮次和正反方向分别分析，并汇总成功次数、失败次数、阻断原因、完成度、重试和时延指标。
- 单 SID 日志继续使用原有结构，保持单次升级分析兼容性。
- 循环日志质量评分改为按每个 SID 的闭环结果计算，并在报告中标出具体失败轮次和方向。

### 界面与操作

- 当前报告和归档报告统一采用页签样式，报告阶段时间线与实时状态机保持一致。
- 所有应用内弹框均支持按 `Enter` 确认，并确保只触发当前可见弹框。
- Node RSSI 统一规范为负数 dBm 显示和门限判断，例如 `-58 dBm`。
- 为主窗口增加清晰边框和阴影，在白色桌面或其他白色窗口上仍可辨识边界。

## 升级说明

- 已安装 v0.1.2 的用户可以直接使用工具内“检查更新”下载并安装 v0.1.3。
- v0.1.0 或 v0.1.1 仍需先手动升级到 v0.1.2 或更高版本，之后即可使用工具内在线升级。
