# v0.2.2

这是 OTA 测试平台的稳定性与目标准确性更新，重点修复升级失败后的 MQTT 重连、Node 目标数量偏差，以及多人测试时 Patch 文件互相覆盖的问题。

## MQTT 连接恢复

- 修复 OTA 失败后重新连接时访问已释放 `SemaphoreSlim`，导致 MQTT 无法恢复且升级按钮持续置灰的问题。
- 替换连接失败时立即清除旧客户端引用，并释放连接失败的新客户端。
- MQTT 客户端和重连传输层的释放操作改为幂等，重复释放不再破坏后续连接。

## Node 发现与任务范围

- Node 唯一身份调整为“设备类型 + 2 字节 Node ID”，允许同一 Extender 下不同设备类型使用相同 Node ID。
- 同一设备类型内的重复 Node ID 仍会作为协议错误拒绝。
- 动态 Node 任务保存添加任务时实际勾选的 Node，执行时只复核这些候选节点，不再扩展到同一 Extender 下的全部匹配节点。
- 添加任务时按 Extender 和版本集中列出起始版本不匹配的 Node，避免重复错误信息难以定位。
- 版本复查和任务完成后的本地状态更新同时按 Node 类型与 Node ID 定位，避免同 ID 的其他类型节点被误计入。

## Patch 命名与 Gateway 长度门禁

- 自动生成的正向、反向 Patch 文件名增加 10 位 Unix 时间戳后缀，例如 `socket-v1-to-v2-1788317157.patch`。
- 同一次制作的正向和反向 Patch 使用相同时间戳，便于配对识别，并降低多人向同一目录发布时互相覆盖的风险。
- MQTT `net.file` 继续下发完整 Patch 文件名，不使用短别名。
- 按新版 Gateway 缓冲区执行 UTF-8 字节长度预检：完整 URL 最多 255 字节，文件名最多 63 字节；超限时在添加任务或执行预检阶段阻止下发并显示具体长度。

## 升级说明

- v0.2.1 可通过工具内更新直接升级到 v0.2.2。
- 本版本要求 Gateway OTA 请求结构使用至少 `address[256]` 和 `file_name[64]`，并确保字符串复制后以 `\0` 结尾。
- Patch 内容格式、Manifest 字段、任务模板和历史报告数据库保持兼容。
