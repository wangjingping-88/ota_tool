# v0.2.7

这是 OTA 测试平台的升级可靠性增强版本，重点补齐 Node 失败重试配置、部分成功诊断，以及 Gateway 启动请求的业务受理与有限幂等重发闭环。

## Gateway 启动受理与幂等重发

- 支持解析 `cmd=10` 启动受理应答，并兼容 MQTT 消息外层数组。
- 启动请求发出后先显示“等待网关受理”，默认等待业务应答 5 秒，不再把 MQTT 发布成功直接视为任务已建立。
- 收到 `ACCEPTED` 或 `DUPLICATE` 后绑定网关返回的 SID，并继续通过 `cmd=8/9` 核对真实任务状态和最终结果。
- 未收到受理应答时先查询；只有查询明确返回 `TASK_NOT_FOUND` 才会重发原请求。
- 同一次启动最多尝试 3 次；重发严格复用原 MQTT 主题序号和完整 JSON 参数，避免重复创建 SID、下载和下游升级任务。
- 查询超时只标记“任务状态未知”并继续有限退避查询，不以超时证明任务不存在，也不会据此重发启动请求。
- `TASK_SEQ_CONFLICT` 等业务拒绝会明确显示“请求未受理”；`REQUEST_ID_RESERVED` 只查询已有恢复任务，不自动换序号或覆盖任务。
- 报告增加启动受理结果、SID、重复请求标记和拒绝原因，便于区分“任务未建立”和“受理后升级失败”。

## Node OTA 重试与诊断

- Node 升级增加失败处理策略：整批失败，或隔离失败节点并由固件自动重试一次。
- 重试策略随单次任务、循环任务、队列、历史模板和模式设置一起保存，执行时按快照下发 `node_retry_count`。
- 支持 `PARTIAL_SUCCESS`、实际重试轮次及最终失败节点列表；失败节点按 Extender ID、Node 类型和 Node ID 三元组区分。
- 部分成功作为独立终态展示，不计为成功，不再继续循环和后续队列任务。
- 状态查询返回 `RESOURCE_UNAVAILABLE` 时退避重试；请求了重试但网关未回显策略时提示能力尚未确认。

## Patch 门限与界面

- 路灯控制器（Node 类型 7）的 Patch 上限调整为 44 KiB，并在添加任务及执行预检时提前拦截超限文件。
- 其他 Node 类型的 Patch 上限保持 52 KiB。
- 调整 Node 失败处理策略选项和说明文字的行内对齐。

## 升级说明

- v0.2.6 可通过工具内更新直接升级到 v0.2.7。
- 旧 Gateway 固件未提供 `cmd=10` 时，工具仍会通过 `cmd=8/9` 查询确认任务是否建立。
- Node 重试需要目标固件支持 `node_retry_count`；未回显时工具会给出明确提示。
- Patch、任务历史、报告数据库和既有本地设置保持兼容。
