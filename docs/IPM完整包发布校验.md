# IPM 完整包发布误要求差分清单

日期：2026-09-28。

## 现象与原因

MCU bin 已经可以不带外部清单导入，但点击「Patch 发布」仍提示缺少 Package Manifest。

导入流程将未知 MCU 版本标记为未验证，发布入口却使用同一标记过滤所有文件，把完整包误当成未验证的差分包。即使放开入口，上传前仍会读取空版本并执行升级版本校验，因此必须同时修复两个位置。

## 处理

发布入口和上传前共用文件发布校验：MCU 完整包允许版本未知，验证当前模式、包类型、长度、MD5 和 SHA256；差分包仍须有有效差分清单。升级执行继续要求有效版本。用户不需要另行提供 `.ipm.json`。

这只是 MCU 尚无内嵌版本标识期间的临时兼容，由 `AllowTemporaryUnknownMcuVersionPublishing` 明确限定。已识别版本的 MCU 包始终执行严格的版本一致性、链接地址及内容校验，不走临时分支。后续固件加入标识并接通识别时，必须删除或关闭该开关，恢复所有 MCU 包的严格发布校验，同时将未知版本发布测试改为拒绝场景。

## 回归验证

- 不带清单的 MCU bin 导入并重新加载后，可以进入发布确认，确认列表包含该文件。
- 版本未知的 MCU 包不能启动升级。
- 无效差分包仍被发布检查拒绝。
- 已识别 MCU 版本不一致或未经验证时仍拒绝发布。
- 在确认后修改 MCU 文件，上传前检查拒绝该文件；再次点击发布也不能绕过哈希检查。

调试同类问题时，应沿着导入、目录恢复、发布确认、实际上传、升级预检检查所有校验入口，区分文件可传输与固件可执行，避免只修复第一道检查。
