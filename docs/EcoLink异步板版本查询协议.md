# EcoLink `cmd=100` 异步查询协议（WIoTa 2.0）

以 `D:\code\EcoLink\docs\WIoTa终端和extender通信协议\Extender异步通信协议v2.0.md` 为准。外层 MQTT JSON 的 `ver: "v2.0"` 与内层 WIoTa 二进制应用帧是两层协议；不能只检查 JSON 版本而沿用旧应用帧位布局。

## 查询职责

- Gateway `cmd=3` 鉴权列表提供承载板的完整 WIoTa ID、设备类型和同步端软件版本；其中同步端 `device_type=2`。这个编号属于 Gateway 鉴权端点类型，与 WIoTa 应用帧及固件标识中的 `ExtenderS=3` 不同，不能混用。
- Node 列表通过 `cmd=100` 发送应用命令 `0x18`，接收 `0x19` 分页响应。
- Sync/Async 信息通过 `cmd=100` 发送应用命令 `0x27`，接收 `0x28` 响应；Async 升级使用响应中的异步端软件版本。
- 工具只收发 2.0 应用帧，不发送旧命令、不回退旧帧解析。IPM 的查询规则独立。

## MQTT 透传与固定头

Node 列表请求的 JSON 示例：

```json
{"cmd":100,"ver":"v2.0","src":0,"dst":1821373,"fmt":"hex","uc":"000608"}
```

信息查询仅将 `uc` 改为 `C00908`。`dst` 使用鉴权列表中的完整承载板 ID；主题末尾的序号用于发布，不是响应事务号。Gateway 上行允许单个 JSON 对象或数组，响应项须有 `cmd=100`、`src`、`fmt` 和 `data`。仅有 `uc.res` 的发送 ACK 不作为业务响应。`fmt` 支持 `hex` 和 `base64`。

应用帧固定头按小端位序排列：`Property(6) + Cmd(6) + SrcType(6) + DestType(6)`，共 3 字节。下行查询为服务器类型 `0` 发往异步端类型 `2`，属性为 `0`。上行响应必须是异步端类型 `2` 发往服务器类型 `0`，携带源地址和数据长度。列表响应固定头为 `49 26 00`，信息响应为 `09 2A 00`。

按 Property 的 bit4、bit3、bit2、bit1、bit0 顺序解析可选包序号、源地址、目的地址列表、唤醒周期和 DataLen。bit5 为保留位，必须为 `0`；包序号和源地址不可为 `0`，唤醒周期为 `1～44 s`。DataLen 必须等于实际数据字节数，不能有截断或尾随字节。

## `0x19` Node 列表

数据区为 `本页设备数 + 页号 + 总页数 + 设备总数 + N × (Node 类型 + Node ID LE16 + RSSI 绝对值 + 软件版本)`。分页头固定 4 字节，每页最多 50 项，最多 6 页，总设备数最多 255。空列表回复 `00 00 01 00`。

工具按页号去重，收齐全部页后发布完整列表；各页的异步地址、总页数和设备总数必须一致。Node 身份是“类型 + 2 字节 ID”，同类型重复或零 ID 被拒绝。Node 类型限 `4～63`，其中 `4～9` 为内置类型，`10～63` 可自定义。RSSI 字节为绝对值 `0～200`，显示时取负；`0` 表示离线。版本 `0/255` 显示为未知，不能作为升级目标。

## `0x28` Extender 信息

数据区固定 6 字节：`sync_version + sync_rssi_abs + sync_snr_i8 + async_version + online_count + total_count`。RSSI 绝对值范围 `0～200`，SNR 范围 `-30～30`；在线数不得大于总数，总数可以超过一页的 50 项，上限为 255。

原始版本字节用于 Patch 校验和 MQTT 下发；显示时按十进制一位小数转换，例如 `1 → 0.1`、`23 → 2.3`。

## 调度与失败处理

- 同一完整 Extender ID 的 `0x18` 和 `0x27` 查询共用一把锁，严格串行；不同 Extender 并行。
- 通过 Gateway 上行主题、顶层 `src` 和应用层 Cmd 关联响应。每次等待 5 秒，最多两次，重试前排空 500 ms 过期响应。
- 收齐分页、超时或取消后立即注销处理器；重复页内容冲突、页数和总数不一致均明确报错。
- 单板失败不丢弃其他 Extender 的成功结果；所有 `0x28` 查询失败时清空 Async 可升级目标。
