# OTA 测试平台

该目录包含 Windows OTA 测试平台的可运行原型，目标框架为 `.NET 8 + WPF`。

## 当前能力

- 传统模式：Gateway / Sync 的定向或广播升级；以 Gateway `cmd=6` 最终结果消息作为终态依据；不显示日志分析和 `cmd=8/9` 轮询。
- EcoLink 模式：Gateway / Sync / Async / Node，接收 `cmd=6` 结果并使用 `cmd=8/9` 轮询确认终态。
- MQTT 服务端与客户端分离：本机可作为独立 Broker 服务端；工具客户端可在本地 Broker 与公网 / 外部 Broker 之间切换，分别配置端口和认证信息。
- HTTP 文件来源可选：支持本地 HTTP Range 服务或公网 HTTP 服务；本地服务支持 `HEAD`、完整 `GET`、单段 `Range GET`、`206 Partial Content`、`Content-Range`。
- 启动门禁：启动 OTA 前自动检查 MQTT 已连接、任务/容量参数及本地 HTTP 的 `HEAD`、Range 和完整 MD5；未通过即拒绝发送 `cmd=5`。
- Patch 导入：复制到本地 HTTP 根目录，计算 MD5、SHA256 和容量门禁。
- SFTP 发布：支持密码或 OpenSSH 私钥认证、服务器 Host Key SHA256 指纹校验、临时文件上传和原子重命名；发布后执行 HTTP HEAD/Range 验证。
- 差分引擎：提供标准接口、Package Manifest 和安全门禁。未通过黄金样本、宿主恢复和真实 Bootloader 验证前，默认禁止生成 Patch，只允许导入已有 Patch。
- 报告：SQLite 索引、JSON 和 HTML 导出；传统模式报告固定标注“日志解析不支持”。
- EcoLink 日志分析：仅允许调用已封装的外部日志分析 EXE；传统模式主动拒绝。
- 任务控制：支持取消、EcoLink 轮询暂停/恢复；未收到 Gateway 最终结果时按任务超时自动结束。EcoLink 状态查询按 5、10、20、30 秒退避重试。
- Node 任务：支持 `node_type=2～63` 和 `ExtenderID: NodeID,NodeID` 显式映射，限制为 16 个 Extender、256 个唯一 Node。
- 循环测试：支持独立的正向、反向 Patch，按 `V1 → V2 → V1` 执行并在失败、取消、超时时停止。

## 构建与运行

```powershell
dotnet restore tools\ota_tool\OtaTool.sln
dotnet build tools\ota_tool\OtaTool.sln --no-restore
dotnet run --project tools\ota_tool\OtaTool.App\OtaTool.App.csproj --no-build
```

## 冒烟测试

```powershell
dotnet run --project tools\ota_tool\OtaTool.Core.SmokeTests\OtaTool.Core.SmokeTests.csproj --no-build
```

冒烟测试覆盖模式约束、Patch 容量、JSON 设置、HTTP Range、内嵌 MQTT Broker 与 MQTT 客户端、
`cmd=5/6/8/9` 编解码、传统/EcoLink 任务终态、循环任务、Manifest、SQLite 报告和 HTML/JSON 导出。

## 上线前配置

- MQTT 服务端：如需本机提供 Broker，填写本地监听端口及可选认证信息，再启动“本地 Broker”。
- MQTT 客户端：选择“连接本地服务端”或“连接公网服务端”。公网模式填写 Broker 地址、端口、账号密码和 TLS 参数；密码/私钥口令只能保存到 Windows Credential Manager，不能写入 JSON 配置或报告。
- SFTP：必须填写服务器 Host Key 的 SHA256 指纹；未提供指纹时，发布器拒绝连接。
- HTTP 文件服务：可选择本地 HTTP Range 服务或公网 HTTP 服务。导入 Patch 后如使用本地来源，先启动本地服务；如使用公网来源，填写 Patch 所在目录的公网基础地址。工具将本地 Patch 放到 `%LOCALAPPDATA%\OtaTool\http-root`。
- 差分生成：在 `partition-bsdiff-lzzip` 原生引擎通过设计文档第 5.4.3 节的全部验收前，不得解除生成门禁。
