# OTA 测试平台测试清单

本次本地运行包：`artifacts\release-candidate-v0.2.9\OtaTool.App.exe`。

## 启动与环境

1. 启动程序，确认左侧导航可以定位到环境、任务、循环、日志和报告区域。
2. 在“MQTT 服务端”填写本地端口、用户名和密码，点击“启动本地 Broker”；再次点击同一按钮，确认服务停止。
3. 在“MQTT 客户端”选择“连接本地服务端”，点击“连接 MQTT”；再次点击同一按钮，确认客户端断开。切换到“连接公网服务端”，填写公网地址、端口、用户名、密码及 TLS 参数后重复验证。
4. 选择“使用本地 HTTP 服务”，启动本地 HTTP Range 服务并确认显示的端口与设置一致；再次点击同一按钮，确认服务停止。
5. 选择“使用公网 HTTP 服务”，填写公网 HTTP 基础地址，确认“当前 OTA 下载地址”由该地址与 Patch 文件名组成。
6. 修改 MQTT/HTTP/SFTP/日志配置后点击“保存设置”，重启程序确认普通设置已恢复；制作一次正向和反向 Patch 后重启，确认两个 Patch 名称自动恢复；密码和私钥口令应从 Windows Credential Manager 恢复，不应出现在 JSON 设置文件中。
7. 在 EcoLink 与传统模式分别设置不同的页面、Gateway ID、MQTT/HTTP/SFTP、Patch 目录、升级类型、循环间隔和报告范围，往返切换并重启，确认两套状态互不覆盖；`settings.json` 应包含 `modeWorkspaces.EcoLink`、`modeWorkspaces.Traditional` 与 `activeMode`，Credential Manager 使用带模式前缀的键。
8. 在 EcoLink 模式制造一次升级失败状态后切换传统模式，确认传统模式不显示该失败状态；再切回 EcoLink，确认原状态仍保留。MQTT 已连接、本地服务运行、Patch 发布中或升级进行中时应禁止切换模式。

## 传统模式

1. 切换到传统模式，升级类型只能看到“网关升级、拓展器-同步升级”；日志分析导航不显示。
2. 分别测试指定 ID 和广播。广播时不填写目标 ID，升级 JSON 中不得带 `targets`，也不得出现广播时间字段。
3. 启动任务后验证不会发送或依赖 `cmd=8/9`；仅 Gateway 上报 `cmd=6` 的最终结果后结束。
4. 不上报最终结果，确认任务在设置的超时时间后自动变为超时。

## EcoLink 模式

1. 切换到 EcoLink 模式，确认可选择“网关升级、拓展器-同步升级、拓展器-异步升级、节点升级”。
2. 连接后向 `ucchip/up/sgw/<gateway_id>/<seq>` 发布一条上行消息，确认界面显示“已观察到上行消息”；未观察到时 EcoLink 任务必须被启动门禁阻止。
3. Sync/Async 定向任务最多 16 个 Extender；Gateway 协议请求中的设备类型分别是 `iote`、`ex_mcu`。
4. Node 任务填写 `node_type`（2～63）和 `ExtenderID: NodeID,NodeID` 映射；确认单任务最多 16 个 Extender、256 个唯一 Node。
5. 启动后确认先发送 `cmd=5`，再按策略发送 `cmd=8`；接收 `cmd=9` 后更新状态。查询超时应按 5、10、20、30 秒退避。
6. `cmd=6` 到达后不直接结束，必须等待 `cmd=8/9` 确认最终状态。

## Patch、发布与循环

1. 先后导入内容完全相同的 A/B 固件，确认工具通过 SHA256 提示“镜像相同，请重新导入”，且不得生成 Patch。
2. 导入 Patch 后确认程序显示 MD5、SHA256、长度，并将文件复制到本地 HTTP 根目录。
3. 若旁边存在 Package Manifest，确认自动加载旧/新版本和目标类型；Manifest 的 `patchVerified=false` 时不得启动。
4. 启动任务前断开 MQTT、停止 HTTP 或篡改文件，确认门禁阻止发送 `cmd=5`。
5. 配置 SFTP Host Key SHA256 后测试密码和 OpenSSH 私钥上传；确认临时文件上传、原子重命名、HEAD/Range 与完整 MD5 校验。
6. 导入正向与反向 Patch，测试 `V1 → V2 → V1` 循环。任一步失败、取消或超时必须停止后续步骤。

## 报告与日志

1. 完成或取消任务后导出 HTML、JSON；确认报告含模式、协议适配器、Patch 哈希、时间线和最终状态。
2. 刷新历史报告，确认 SQLite 中的任务显示在列表中。
3. 传统模式报告固定显示“日志解析不支持”。
4. EcoLink 模式提供日志分析器 EXE 与日志目录后运行分析，确认 JSON 分析结果路径写入当前报告。

## IPM MCU 正式流程（v0.2.9）

1. 升级配置没有 MCU 验证模式或手填版本。EcoLink、传统、IPM 工作区切换仍正常。
2. MCU 导入无外部清单的完整 rtthread.bin，显示正确 v0.1/v0.2、IPM_GD32L233、硬件版本和 APP 大小。
3. 导入含 UBoot 的 rtthread.bin，原样保留全包，长度和哈希与用户输入文件一致；用户源文件不修改。
4. 旧直启 bin、错误型号、无效版本、头/数据 CRC 错误、无效向量及超 256 KiB 全包 均拒绝导入。
5. 选择正向 v0.2、反向 v0.1，自动显示旧 1 新 2，生成单次及循环任务；只有目标包而无当前版本镜像时不猜测旧版本。
6. 旧设置含验证模式字段仍能加载，重新保存不含该字段；旧手填联调包及队列不能绕过正式镜像预检。
7. 发布确认后篡改镜像或清单版本，实际上传及执行前拒绝。实际 HTTP MD5 必须是完整 BIN MD5。
8. 实板确认业务 UART 115200、日志 460800，等待同 SID 的 READY → COMMIT → UBoot 更新 → 新 APP 确认 → cmd=9 最终成功。仅 READY/进度完成不结束任务；成功后测试反向和循环。

9. 包内 UBoot 与设备 UBoot 内容不同，升级后 APP 更新成功，前 32 KiB 逐字节不变。初始通过烧录器安装 API 2 基线，OTA 不提供 UBoot 更新入口。
