# IPM OTA 工具联调心得

## 先区分三个身份

MQTT 初始升级主题序号是 `task_seq`，每次状态查询产生新的 `query_seq`，网关分配 `session_id`。重发启动保留初始请求和全部参数。只有明确查询不到任务才能重发，查询超时只是状态未知。

## 用会话终态判断升级完成

首轮广播字节发送完毕不代表 MCU 已持久化或新 APP 已启动。补包、Flash 写入、提交和重启核验可能继续很久。模拟器应主动构造 `COMMIT`、`BOOT_VERIFY`、错 SID、错网关以及 `cmd=6` 成功提示，确认工具仍等待当前会话最终状态。

## 独立验证完整镜像

烧录与 OTA 使用同一 rtthread.bin。APP 信息在完整文件 0x8000，向量在 0x8200；工具原样导入全包，MD5、SHA256、Journal 长度和包 CRC 均包含前 32 KiB。不要把旧 APP-only 包作为新全包，也不要在工具里提取 APP 后计算任务哈希。

设备下载和校验全包后，由 UBoot 从外部文件 0x8000 开始搬运 APP 到 0x08008000。包里的 UBoot 内容即使不同也不安装，设备 UBoot 只能通过烧录器更新。掉电测试应特意让包内和设备 UBoot 不同，逐字节检查前 32 KiB 保持不变。

CRC 区分头区 [0x8000,0x803C)、APP 数据区 [0x8040,末尾) 和全文件。安装后不能拿内部 APP CRC 与整包 CRC 直接比较，也不能要求设备 UBoot 与包内 UBoot 相同；应核验源整包 CRC，以及源 APP 与安装后 APP 的信息和正文 CRC 一致。

完整包 256 KiB 会改变 NOR Journal 和 boot_cfg 地址，APP 与 UBoot 的独立契约必须同步，首次迁移使用烧录器安装 API 2 基线。不要只扩大工具门限而漏改网关/WIoTa/MCU 的包长、位图和分区。


## 不混淆版本来源

鉴权表返回同步端版本，不是 MCU 版本。首次 MCU 旧版本来自受控部署信息；后续版本仅接受同会话成功事实。日志阶段解析缺失时显示证据不足，不能把日志评分当成升级成功。

MCU 固定正式升级，工作区、队列、任务中均删除验证模式字段。旧配置可加载，但旧无信息头包不能通过正式校验。当前没有独立 MCU 版本查询，继续等待匹配会话 cmd=9 最终成功；READY、COMMIT、BOOT_VERIFY 及传输进度都不能替代该结果。只有最终成功才推进预计运行版本和成功缓存。

## 检查选择与日志的完整路径

新增任务类型时不仅要更换显示名，还要覆盖设备勾选回调。IPM 的同步与 MCU 类型曾漏在选择同步分支之外，导致界面已勾选但固定目标列表为空。回归应实际切换勾选状态并检查任务中的目标 ID。

状态栏和日志曾使用不同的文案入口：状态 getter 已替换模式名称，但日志直接写入原字符串。写日志时也需应用模式文案转换，并兼容已缓存的日志显示；模式切换按钮名称按用户要求始终为 EcoLink 模式。

## 历史报告按模式查询

报告表已有模式字段，仅在界面加载完成后筛选仍可能出错：切换模式时，旧模式的异步查询晚返回会覆盖新模式列表。应在 SQL 中先按 `mode` 筛选再排序截断，并给每次界面加载分配序号；模式或归档范围变化后，过期结果不得写回。切换时立即清空旧列表和多选状态，避免用户在新模式下操作旧报告。单任务与测试计划报告都要覆盖此规则。

## 推荐回归方式

核心层使用模拟 MQTT 验证协议与故障分支；界面层注入独立数据目录和内存凭据，验证模式切换、包过滤、版本展示、队列和重启恢复，不读写用户真实凭据。相关回归陷阱见 [[IPM接入时的静态测试迁移记录]]。
